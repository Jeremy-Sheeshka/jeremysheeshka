# Rhythm-App: What You Can Build

## What rhythm-app provides (the engine)

| Capability | Key Global | What it does |
|---|---|---|
| Staff notation renderer | `MusicRhythmImage` | Draws rhythms as SVG with notes, rests, beams, ties, triplets, time sigs |
| Rhythm data model | `MusicRhythm`, `MusicBar`, `MusicRhythmComponent` | Tick-based timing (144 = quarter note), 12 time signatures, swing support |
| Random generator | `MusicRandomRhythmGenerator` | Generates random rhythms with configurable note lengths, rest %, dots |
| Playback sequencer | `MusicRhythmPlayer` | count-in → play → tap → count-out state machine |
| Tap evaluation | `MusicRhythmPlayer` | Timing tolerance grading: correct (green), nearly (yellow), wrong (red) |
| Edit mode | `MusicRhythmImage.startEditMode()` | Click/keyboard note insertion and deletion |
| Quiz framework | `MusicOpgave` | Server-backed exercise flow with scoring, tips, results |
| Melodic notation | `MusicNodebillede`, `MusicTone`, `MusicKlaviatur` | Treble/bass/alto/tenor clefs, pitch model, virtual piano |
| Audio | `MusicRhythmSounds` (Howler.js) | Metronome clicks, rhythm sounds |
| Multi-language | `Music` global | 20+ UI languages, 15+ note naming systems |

## What rhythm-reader already wraps

- **Free Play** — solo practice with metronome, drawing canvas, counting aids, settings
- **Co-Op** — two-player "trade fours" with A/B bar ownership overlays
- **Dinosaur Mode** — standalone canvas runner game with progressive difficulty
- **Rhythm Bank** — record, store, share rhythms via Firebase REST API
- **Onboarding** — guided tour and easy/hard mode gate

## Wrapper pattern (for building new projects)

1. Fetch drill HTML as string via `fetch('/games/rhythm-app/exercise/720/')`
2. Strip frame-bust protections with regex replacements
3. Inject `embed-bridge.js` (patches engine runtime, adds cursor/aids/co-op)
4. Inject `embed-overrides.css` (hides drill-native UI chrome)
5. Set as `iframe.srcdoc`
6. Communicate via `postMessage` protocol (praxis-metro, praxis-tap, etc.)

## Ideas for new projects around rhythm-app

### Easy (wrapper-level, same pattern as rhythm-reader)
1. **Rhythm Dictation** — play a rhythm, user writes it on staff using edit mode
2. **Call & Response** — play 1 bar, user taps it back, progressively longer
3. **Tempo Trainer** — auto-increase BPM each successful round
4. **Rhythm Quiz** — multiple choice "which rhythm did you hear?" using svarknapper

### Medium (new UI on top of engine)
5. **Rhythm Composer** — full multi-bar editor, save to rhythm bank, shareable links
6. **Rhythm Challenge** — timed exercises with leaderboard (use existing `/hi` endpoint)
7. **Polyrhythm Explorer** — layer two subdivisions, visualize alignment
8. **MIDI Input** — connect drum pad/controller for tapping instead of keyboard

### Ambitious (larger scope)
9. **Rhythm Visualization** — animated visuals (bouncing ball, pulse rings) instead of notation
10. **Networked Ensemble** — extend co-op to 3-4 players via WebSocket
11. **Sight Reading Course** — progressive curriculum using opgave framework + onboarding pattern
12. **Rhythm Recording Studio** — multi-track recording, layer patterns, export audio

## Key files to know

| File | Role |
|---|---|
| `public/games/rhythm-app/` | The engine (never modify) |
| `public/games/rhythm-reader/embed-bridge.js` | Bridge pattern to study (~26KB, most fragile file) |
| `public/games/rhythm-reader/free-play.html` | Best example of the wrapper pattern |
| `public/games/rhythm-reader/HANDOFF.md` | Architecture docs, postMessage protocol |
| `public/games/rhythm-app/_harness/index.html` | Dev harness for testing engine in isolation |
| `netlify/functions/rhythms.mjs` | Firebase-backed rhythm CRUD API |
| `netlify/functions/hi.mjs` | High score/leaderboard endpoint |

## Architecture notes

- No build system — all scripts loaded via `<script>` tags, minified
- Global singletons (IIFEs attached to window)
- embed-bridge.js is the fragile integration point — always verify with `node -c` before deploying
- The engine is a black box — interact only through patched globals and callbacks
- postMessage protocol is the clean interface between parent pages and the engine iframe
