# Rhythm Reader — Bug Fix & Finalization Workflow Playbook

## Your Setup
- **MiMo Code** — full agentic, running right now in this terminal
- **Reasonix + DeepSeek** — full agentic, configured in this repo (`.reasonix/`)
- **Claude Code** — online, strongest general model
- **Qwen 3.8** — online, fast/cheap

## The Project
Rhythm Reader is a music sight-reading game built on Astro 6. Key files:
- `public/games/rhythm-reader/fp-onboard.js` — main overlay engine (notation, tap judging, audio, draw layer)
- `public/games/rhythm-reader/index.html` — Rhythm Bank dashboard
- `public/games/rhythm-reader/free-play.html` — the game page
- `netlify/functions/rhythms.mjs` + `rhythms_local.mjs` — Firebase storage
- Deployed on Netlify, auto-deploys on push to main

## Workflow 1: Bug Hunt (the most common one you'll use)

```
Step 1 — DESCRIBE the bug to MiMo Code
  "The cursor skips beat 3 when tapping in hard mode with 4 bars"
  → MiMo Code reads the relevant code, traces the logic path
  → MiMo Code identifies the likely code region

Step 2 — If the bug is MATH/LOGIC heavy, send to DeepSeek
  "Here's cursorX() and the scheduling loop. The cursor skips beat 3
   in 4-bar hard mode. [paste functions]. What's wrong?"
  → DeepSeek's reasoning strength finds timing/grid math issues

Step 3 — FIX in MiMo Code
  Apply the fix (DeepSeek's suggestion or MiMo's own)
  → MiMo Code edits fp-onboard.js
  → MiMo Code runs `pnpm build` to verify no syntax errors

Step 4 — VERIFY on live site
  Push → Netlify auto-deploys → test in browser
  → MiMo Code can commit and push for you
```

**When to skip DeepSeek**: Simple bugs (wrong CSS class, typo, missing `await`). MiMo Code handles those alone.

**When to definitely use DeepSeek**: Anything involving the cursor math, tap window timing, beam drawing logic, or the uniform grid (`pos()` / `cursorX()` / `uSlot`).

## Workflow 2: Pre-Deploy Verification Checklist

Before pushing a batch of fixes:

```
Step 1 — MiMo Code runs the build
  "Run pnpm build and tell me if there are any errors"
  → Catches syntax errors, missing imports, type issues

Step 2 — MiMo Code reviews the diff
  "Show me what changed since last commit"
  → You review the diff visually

Step 3 — DeepSeek reviews safety rails (optional but valuable)
  "Here's my diff. Did I violate any of these constraints?
   [paste HANDOFF.md safety rails section]"
  → DeepSeek checks: cursor math preserved? 2-bars-per-row?
    masterGain-based Stop? tap armed at scheduling?

Step 4 — MiMo Code pushes
  "Commit and push with message: fix [description]"
  → Auto-deploys to Netlify

Step 5 — Test on live site (you, in browser)
  Netlify functions don't work on localhost, so test the live URL
```

## Workflow 3: "Something Broke After the Last Push"

```
Step 1 — MiMo Code checks git history
  "What changed in the last 3 commits?"
  → Identifies what was touched

Step 2 — MiMo Code reads the changed files
  → Traces the regression

Step 3 — If unclear, DeepSeek analyzes
  "This worked before commit X, now it doesn't. Here's the diff."
  → DeepSeek spots what the change broke

Step 4 — MiMo Code reverts or fixes
  "Revert that commit" or "Fix the regression"
  → Push, verify on live
```

## Workflow 5: Cross-Browser / Device Testing Issues

```
Step 1 — MiMo Code reads the relevant code
  "Here's the CSS/JS for [component]. It breaks on Safari."

Step 2 — DeepSeek for compatibility reasoning
  "This CSS works in Chrome but breaks in Safari. Here's the code.
   What's the Safari-specific issue?"
  → DeepSeek knows browser quirks well

Step 3 — MiMo Code applies the fix
  → Build, push, test
```

## Workflow 6: Firebase / Netlify Functions Debugging

```
Step 1 — MiMo Code reads the function code
  "Read netlify/functions/rhythms.mjs and tell me what it does"

Step 2 — MiMo Code checks for obvious issues
  → Missing error handling, wrong Firebase path, etc.

Step 3 — DeepSeek if the logic is complex
  "This function intermittently fails. Here's the code and the error."
  → DeepSeek reasons about async issues, race conditions

Step 4 — MiMo Code fixes, pushes, tests on live site
  (Remember: functions don't run on localhost)
```

## Quick Reference: When to Use What

| Situation | Tool | Why |
|---|---|---|
| Simple bug (typo, CSS, missing class) | MiMo Code | Fast, direct |
| Cursor/timing/beam math bug | DeepSeek → MiMo Code | Math reasoning |
| "It broke after last push" | MiMo Code (git log) → DeepSeek | Both needed |
| UI polish / copy changes | MiMo Code | No reasoning needed |
| Pre-deploy safety check | DeepSeek | Reviews constraints |
| Firebase function issue | MiMo Code → DeepSeek | Read first, reason second |
| Build fails | MiMo Code | Direct error output |
| Cross-browser issue | DeepSeek | Compatibility knowledge |
| Quick CSS question | Qwen | Cheap, fast |

---

## The Golden Rule for Bug-Fixing Phase

**Start with MiMo Code** (it reads your actual code and runs builds).
**Escalate to DeepSeek** when the bug involves math, timing, or reasoning.
**Escalate to Claude Code** when you're truly stuck and need the strongest model.
**Use Qwen** for quick questions that don't need file access.

You don't need all four for every bug. Most bugs: MiMo Code alone. Hard bugs: MiMo Code + DeepSeek. Stuck: add Claude Code.
