# How to Use Your AI Tools on Rhythm Reader

You have 4 tools. Here's exactly when and how to use each one on this project, with real prompts you can copy-paste.

---

## Tool 1: MiMo Code (this tool) — Your Daily Driver

**What it's good at**: Reading your actual files, editing code, running builds, pushing to deploy.

### Real prompts to use:

**Understanding the code:**
```
Read fp-onboard.js and explain the flow from when the user clicks Play
to when the cursor finishes. What functions are involved?
```

```
Map out all the global variables in fp-onboard.js and what each one tracks.
```

**Finding bugs:**
```
The cursor doesn't land on the notehead when sixteenth notes are beamed.
Read fp-onboard.js and trace the cursorX() and pos() functions —
are they using the same grid math?
```

```
The draw canvas doesn't work after switching from guided to free mode.
Read the draw-related functions and find where the canvas gets reinitialized.
```

**Quick fixes:**
```
The gear icon is too small on mobile. Fix the CSS in the navbar.
```

```
Update the Free Play gate text from "Are you new to reading rhythms?"
to "Have you read rhythms before?"
```

**Build + deploy:**
```
Run pnpm build and show me any errors.
```

```
Commit all changes with message "fix: [description]" and push.
```

## Tool 2: DeepSeek (via Reasonix) — The Brain

**What it's good at**: Reasoning about math, timing, logic, and complex code behavior.

### Real prompts to use:

**Cursor/timing math (DeepSeek's sweet spot):**
```
I'm debugging the cursor in a rhythm game. Here's the math:

  function pos(o) {
    var perRow = L.rowCap * 16;
    var row = Math.floor(o / perRow);
    var local = o - row * perRow;
    var x = L.LM + (local + 0.5) * L.uSlot;
    var cy = row * L.ROW_H + L.CY0;
    return {row: row, x: x, cy: cy};
  }

  function cursorX(v) {
    var ri = rowInfo(v);
    var local = ri.local;
    if (local >= ri.rowBars * 16 - 0.5) {
      local = ri.rowBars * 16 - 0.5;
    }
    var x = L.LM + (local + 0.5) * L.uSlot;
    ...
  }

The cursor is supposed to land exactly on each notehead when the
metronome click sounds. But it seems to drift slightly on the last
beat of a 4-bar row. Is there an off-by-one or rounding issue?
```

**Tap window reasoning:**
```
In this rhythm game, tap judging uses WIN=0.17 seconds. The audio
schedules beats at exact sixteenth-note intervals. Early taps are
guarded by `t < tapMusicStart - WIN`. Is 170ms the right window
for a 90 BPM sixteenth-note grid? What should it be?
```

**Beam drawing logic:**
```
Here's the beam drawing code for sixteenth notes. The secondary beam
should never poke past an adjacent stem. Review this logic and tell
me if the stub cap calculation is correct:

  [paste drawBeams function]
```

**Review a fix before deploying:**
```
I fixed a bug where the cursor jumped at barlines. Here's the diff:

  [paste git diff]

Did I break anything? Check against these constraints:
- cursorX() and pos() must use the same uniform grid
- 2 bars per row, no per-barline margin
- masterGain-based Stop must still work
```

## Tool 3: Claude Code (online) — The Heavy Hitter

**What it's good at**: Hardest problems, polished output, nuanced judgment.

### When to reach for it:

**You're stuck after trying MiMo + DeepSeek:**
```
I've been debugging this issue for 30 minutes. The Rhythm Bank
doesn't save rhythms with sixteenth notes correctly to Firebase.
Here's the netlify function code: [paste]. Here's the client code
that sends the data: [paste]. What am I missing?
```

**Complex multi-file changes:**
```
I need to update the rhythm data format from eighths to sixteenths
across fp-onboard.js, index.html (Rhythm Bank), and the netlify
functions. Design a migration approach that won't break existing
saved rhythms.
```

**Writing/polish (for your ETEC 531 work):**
```
Turn this rough draft into a polished blog post about rhythm
sight-reading pedagogy. Keep the academic voice but make it
accessible. [paste draft]
```

## The Actual Workflow You'll Use Daily

```
1. Start MiMo Code (this tool)
   → "Read fp-onboard.js and find [issue]"
   → MiMo reads code, traces logic, makes edits

2. If the bug is MATH or TIMING related:
   → Copy the relevant functions to DeepSeek
   → "Here's the cursor math. The cursor drifts on beat 3. Why?"
   → Copy DeepSeek's answer back to MiMo Code
   → "Apply this fix: [DeepSeek's suggestion]"

3. If you're STUCK after 2-3 attempts:
   → Switch to Claude Code
   → "I've tried X, Y, Z. Here's the code. What am I missing?"

4. For quick questions:
   → Qwen (fast, cheap)
```

---

## The Key Insight

You don't need all 4 tools for every task. Here's the decision tree:

```
Is it a simple fix (CSS, text, config)?
  → MiMo Code alone

Is it a logic/math/timing bug?
  → MiMo Code finds it → DeepSeek reasons about it → MiMo Code fixes it

Are you stuck?
  → Claude Code

Quick question?
  → Qwen
```

**MiMo Code = hands. DeepSeek = brain. Claude = last resort. Qwen = quick lookup.**
